# Глава 8. Когда виновата версия программы

Самые неприятные ошибки те, что выглядят как ограничения железа. Здесь мы увидим, как
дефект одной версии плагина притворялся «медленной платой», как его опознать по
признакам, найти исправление и подключить его, не ломая систему.

Рецепты 8.6–8.7 про обратный случай: исправления нет ни в одной версии, и его приходится
писать самим.

---

## Рецепт 8.1. Опознать дефект по признакам

**Задача.** Понять, что проблема не в железе, а в конкретной версии программы.

**Решение.** Сопоставить признаки:

| Признак | Где увидели |
|---|---|
| `GstVideoMeta support required, copying frames` | журнал `v4l2codecs` (рецепт 6.6) |
| `cannot have a wl_buffer` у `waylandsink` | при выводе через `cage` |
| Буфер 1440×1080×1,5 вместо 1440×1088×1,5 | арифметика (рецепт 7.5) |
| Синтетический поток 1280x720 (высота кратна 16) работает, настоящий 1080 нет | опыт |

Последний признак решающий: падает только там, где декодер обрезает 1088 строк до 1080.

**Как это работает.** В GStreamer 1.26.2 (это версия Debian 13) плагин `v4l2codecs`
считал **любую** обрезку поводом копировать кадр в обычную память. Нижняя обрезка
1088→1080 есть почти у каждого 1080p-видео. Копия кадра уже не буфер декодера, Wayland
не может принять её как DMABuf, а процессор тратит на копию сотни миллисекунд. Такой же
случай описан для Raspberry Pi; там же указано, что исправление вошло в выпуск 1.26.11.

> [!warning] Подводные камни
> Мы дважды выдвигали другие объяснения («медленное преобразование»,
> «плата не умеет»). Каждое опровергалось только следующим замером. Держите гипотезы
> гипотезами, пока их не подтвердит опыт.

---

## Рецепт 8.2. Найти исправление и убедиться, что оно в исходниках

**Задача.** Не поверить на слово, что «в такой-то версии исправлено».

**Решение.** Скачать исходники и найти признак правки в коде:

```bash
# [плата]
mkdir -p ~/build-gst && cd ~/build-gst
curl -fLO https://gstreamer.freedesktop.org/src/gst-plugins-bad/gst-plugins-bad-1.26.11.tar.xz
tar xf gst-plugins-bad-1.26.11.tar.xz
grep -n 'need_crop\|has_videometa\|copy_frames' \
  gst-plugins-bad-1.26.11/sys/v4l2codecs/gstv4l2codech265dec.c
```

**Как это работает.** В исправленной версии решение о копировании принимается в функции
выбора аллокатора по ответу приёмника (`has_videometa`), а обрезка требуется только при
ненулевом смещении сверху или слева:

```text
988:    self->need_crop |= self->crop_rect_x != 0;
989:    self->need_crop |= self->crop_rect_y != 0;
```

Сравнения высоты (из-за которого и копировалось) больше нет.

> [!warning] Подводные камни
> Выпуск 1.26.11 из той же стабильной ветки, что и 1.26.2, поэтому
> собранный плагин работает с системными библиотеками ядра GStreamer. Плагин из ветки 1.28
> с ядром 1.26 работать не обязан.

## Рецепт 8.3. Собрать один плагин, не трогая систему

**Задача.** Получить исправленный `v4l2codecs`, ничего не устанавливая в `/usr`.

**Решение.**

```bash
# [плата]
sudo apt install build-essential meson ninja-build pkgconf libgstreamer1.0-dev \
  libgstreamer-plugins-base1.0-dev libgudev-1.0-dev libdrm-dev
tmux new -s build
cd ~/build-gst/gst-plugins-bad-1.26.11
meson setup build -Dauto_features=disabled -Dv4l2codecs=enabled --buildtype=release \
  --wrap-mode=nofallback 2>&1 | tee ~/build-gst/meson.log | tail -n 25
time ninja -C build -j2 2>&1 | tee ~/build-gst/ninja.log | tail -n 15
ldd build/sys/v4l2codecs/libgstv4l2codecs.so | grep -E 'codecs|not found'
```

**Как это работает.**

- `-Dauto_features=disabled` выключает все необязательные части, `-Dv4l2codecs=enabled`
  включает нужный плагин.
- `--wrap-mode=nofallback` запрещает meson скачивать недостающие зависимости из интернета:
  если чего-то нет, он остановится с понятным сообщением.
- `-j2`, потому что у платы 1 ГБ памяти. На стенде сборка заняла 6 минут 15 секунд.
- `ldd` показывает, что плагин берёт `libgstcodecs` и `libgstcodecparsers` из **нашей**
  папки сборки (путь вшит при сборке), а остальное из системы.

> [!warning] Подводные камни
> Мы не запускали `ninja install`. Всё живёт в `~/build-gst`, поэтому
> эту папку нельзя удалять, пока плагин в работе.

## Рецепт 8.4. Подменить системный плагин своим

**Задача.** Заставить GStreamer использовать наш плагин вместо системного.

**Решение.** Набор плагинов, где системный `v4l2codecs` заменён нашим:

![Подмена системного плагина](img/08-plugin-mix.svg)

```bash
# [плата]
printf '%s\n' '#!/bin/bash' \
  'rm -rf "$HOME/gst-mix"; mkdir -p "$HOME/gst-mix"' \
  'for f in /usr/lib/aarch64-linux-gnu/gstreamer-1.0/*.so; do' \
  '  [ "$(basename "$f")" = libgstv4l2codecs.so ] || ln -s "$f" "$HOME/gst-mix/"' \
  'done' \
  'ln -s "$HOME/build-gst/gst-plugins-bad-1.26.11/build/sys/v4l2codecs/libgstv4l2codecs.so" "$HOME/gst-mix/"' \
  'ls "$HOME/gst-mix" | wc -l' > $HOME/make-gst-mix.sh && chmod +x $HOME/make-gst-mix.sh
$HOME/make-gst-mix.sh
rm -f $HOME/test/gst-registry-mix.bin
GST_REGISTRY=$HOME/test/gst-registry-mix.bin GST_PLUGIN_SYSTEM_PATH_1_0=$HOME/gst-mix \
  gst-inspect-1.0 v4l2slh265dec | grep -E 'Version|Filename'
```

Нужный ответ:

```text
Filename   /home/user/gst-mix/libgstv4l2codecs.so
Version    1.26.11
```

**Как это работает.**

- Очевидный путь, `GST_PLUGIN_PATH`, на стенде **не сработал**: системный плагин с тем же
  именем вытеснял наш (реестр GStreamer хранит плагины по имени и при совпадении заменяет
  ранее добавленный). Проверка показывала `Version 1.26.2`.
- `GST_PLUGIN_SYSTEM_PATH_1_0` указывает GStreamer **единственное** место поиска
  системных плагинов. Мы кладём туда ссылки на все системные плагины, кроме
  `v4l2codecs`, и наш файл. Двойников нет, вытеснять некого.
- `GST_REGISTRY` задаёт отдельный файл кэша реестра, чтобы обычный кэш не смешивался с
  нашим.

> [!warning] Подводные камни
> - Перед выводами про подмену проверьте `Version` и `Filename`. Мы один раз приняли
>   неудачную проверку за ошибку переменной, хотя причина была в вытеснении.
> - **После установки любого пакета GStreamer пересоздайте набор.** Папка содержит ссылки
>   только на плагины, существовавшие в момент создания. Так мы «потеряли» `alsasink`,
>   поставленный позже.
> - Обновление пакетов GStreamer может разойтись с нашим плагином. Версии стоит закрепить.

## Рецепт 8.5. Проверить, что исправление сработало

**Задача.** Подтвердить результат на настоящем файле.

**Решение.** Запустить вывод через композитор (рецепт 7.4) с переменными из рецепта 8.4.
Скрипт целиком есть в [приложении А](12-appendix-a-scripts.md).

Ответ стенда на файле 1440x1080@60:

```text
last-message = rendered: 2358, dropped: 0, current: 59.69, average: 60.04
real 0m41.138s   user 0m6.304s   sys 0m6.759s
```

60 кадров/с, ноль потерь, около трети одного ядра.

## Рецепт 8.6. Когда исправления нет ни в одной версии: найти место в исходниках

**Задача.** На втором стенде декодер и `kmssink` не договаривались о формате кадра. Найти,
где именно в коде рвётся цепочка, и убедиться, что новая версия не поможет.

**Решение.**

1. Прочитать журнал плагина (рецепт 6.6) у места отказа:

```text
got format NV12_32L32 DRM ....:0x00ffffffffffffff
Supported output formats: video/x-raw, format=(string)NV12_32L32, width=(int)1920, height=(int)800, ...
Peer supported formats: EMPTY
error: No support for 1920x800 format UNKNOWN
```

2. Скачать исходники двух версий, распаковать только нужные папки и поискать признак:

```fish
# [сервер]
mkdir -p ~/bananapi/src; cd ~/bananapi/src
for v in 1.26.11 1.28.9
    curl -fLO https://gstreamer.freedesktop.org/src/gst-plugins-bad/gst-plugins-bad-$v.tar.xz
    tar xf gst-plugins-bad-$v.tar.xz --wildcards '*/sys/v4l2codecs/*' '*/sys/kms/*'
end
grep -rnIE 'ALLWINNER|SUNXI' gst-plugins-bad-1.26.11/sys/ gst-plugins-bad-1.28.9/sys/
```

Ответ (без строк из скопированных заголовков ядра):

```text
gst-plugins-bad-1.26.11/sys/v4l2codecs/gstv4l2format.c:56:  {V4L2_PIX_FMT_SUNXI_TILED_NV12, GST_VIDEO_FORMAT_NV12_32L32, DRM_FORMAT_INVALID, DRM_FORMAT_MOD_INVALID, 0},
gst-plugins-bad-1.28.9/sys/v4l2codecs/gstv4l2format.c:54:  {V4L2_PIX_FMT_SUNXI_TILED_NV12, GST_VIDEO_FORMAT_NV12_32L32, DRM_FORMAT_INVALID, DRM_FORMAT_MOD_INVALID, 0},
```

3. Прочитать таблицу и функцию, которая её разворачивает:

```fish
# [сервер]
sed -n '36,95p' gst-plugins-bad-1.26.11/sys/v4l2codecs/gstv4l2format.c
```

**Как это работает.**

- `DRM ....:0x00ffffffffffffff` в журнале значит, что у формата `NV12_32L32` нет пары
  «fourcc DRM + модификатор». А `kmssink` предлагает кадры только как `DMA_DRM` с
  `NV12:0x0900000000000001` (рецепт 7.6). Это два названия одного и того же кадра, и
  GStreamer их не связывает. Отсюда пустое пересечение.
- В таблице `gstv4l2format.c` две разновидности строк. Если формат GStreamer известен
  (`NV12_32L32`), колонки DRM в строке **не читаются**: пару спрашивают у библиотеки
  (`gst_video_dma_drm_format_from_gst_format`), а та для плиток Allwinner ответа не знает.
  Если формат `UNKNOWN`, пара берётся из таблицы (так сделано для Broadcom `NC12`).
- Поэтому простая замена `DRM_FORMAT_INVALID` в строке ничего бы не дала. Мы сначала
  предложили именно её, и только чтение функции уберегло от бесполезной сборки.
- Итоговая правка из трёх мест (текст в [приложении А](12-appendix-a-scripts.md)):
  пара DRM в строке таблицы; запасной вариант, который берёт пару из таблицы, если
  библиотека молчит; отдельная ветка с «сырыми» шагом и смещением для `ALLWINNER_TILED`
  по образцу ветки Broadcom (зачем она, объясняет рецепт 7.8).

> [!warning] Подводные камни
> - В апстриме есть слой перевода форматов V4L2 в пары DRM (запрос на слияние 7355), но
>   строка Allwinner в 1.28.9 по-прежнему `INVALID`. Описание «поддерживается» не заменяет
>   `grep` по коду.
> - Правка локальная, и у неё есть побочный эффект: для обычного (не `DMA_DRM`) выхода
>   `NV12_32L32` шаги теперь «сырые», и программа, которая читает плитки процессором, их
>   неправильно поймёт. Прямому выводу на экран это не мешает.
> - Распаковывайте только нужные папки (`--wildcards`): весь архив не нужен.

## Рецепт 8.7. Править по одной правке и пересобирать за секунды

**Задача.** Проверять правки в коде по одной, не тратя на каждую полную сборку.

**Решение.**

```bash
# [плата]
cd ~/build-gst/gst-plugins-bad-1.26.11/sys/v4l2codecs
cp gstv4l2format.c gstv4l2format.c.orig
```

После каждой правки:

```bash
# [плата]
diff -u gstv4l2format.c.orig gstv4l2format.c
cd ~/build-gst/gst-plugins-bad-1.26.11 && ninja -C build -j2 2>&1 | tail -n 8
```

Многострочный текст надёжнее вставлять из файла: проверить строку, после которой
вставляем, и вставить командой `r`:

```bash
# [плата]
sed -n '211,213p' gstv4l2format.c | cat -A
sed -i "212r $HOME/test/tiled-branch.c" gstv4l2format.c
```

Когда всё готово, сохранить правку файлом и проверить его:

```bash
# [плата]
diff -u gstv4l2format.c.orig gstv4l2format.c > ~/bpi-m1-notes/v4l2codecs-sunxi-tiled-drm.patch; echo "diff exit: $?"
grep -c 'ALLWINNER_TILED' ~/bpi-m1-notes/v4l2codecs-sunxi-tiled-drm.patch
```

**Как это работает.**

- Первая полная сборка на A20 (два ядра Cortex-A7) заняла 12 минут 4 секунды (182 шага),
  пересборка после правки одного файла 5 секунд: `ninja` перекомпилирует только изменённое.
  Набор плагинов из рецепта 8.4 состоит из ссылок, поэтому подхватывает новую сборку сам.
- Правки применялись по одной, с проверкой после каждой. После первых двух согласование
  заработало (`Selected format DMA_DRM DRM NV12:0x0900000000000001 1920x800`), но ядро
  отвергло буфер, и это дало точную причину для третьей (рецепт 7.8). Применённые разом,
  три правки скрыли бы, какая что лечит.
- `diff -u` с копией `.orig` это проверка, что правка легла: число блоков изменений должно
  совпасть с числом правок. `diff` возвращает 1, когда файлы различаются, это не ошибка.
- `cat -A` показывает невидимое: `$` это конец строки, `^M` признак окончаний строк
  Windows, `^I` табуляция.

> [!warning] Подводные камни
> - Вставка многострочного текста командой `sed '/шаблон/i\...'` у нас молча не сработала:
>   по `cat -A` строка-шаблон была верной, а вставки нет. Причину мы не нашли; вставка из
>   файла через `r` сработала сразу. Не повторяйте `sed` вслепую: повтор удачной вставки
>   создаст дубль.
> - Номер строки для `r` берите из свежего `sed -n ... | cat -A`: предыдущие правки сдвигают
>   нумерацию.
